# 05: اتصال گیت‌وی آروان و کمک هوشمند برای بیان سؤال

**What to build:** سؤال همان قرارداد ثابت، با بیان ساده و متناسب فارسی نمایش داده شود؛ اپ فقط از درگاه آروانِ تنظیم‌شده در سرور مدل مجاز را فراخوانی کند، مصرف را محدود کند و در نبود پاسخ معتبر، فرم ثابت را ادامه دهد. این تیکت حساب کاربران، پایگاه دانش یا موتور ارزیابی را به آروان منتقل نمی‌کند.

**Blocked by:** 03 — فرم عمیق ثابت و مرتبط.

**تصمیم تأییدشدهٔ تجربه:** پس از ثبت هر پاسخ، سؤال مرتبط بعدی خودکار نمایش داده می‌شود؛ استفاده از AI وابسته به دکمهٔ کمک نیست. در نبود بودجه یا قابلیت مجاز، سؤال ثابت فوراً ادامه می‌یابد. با AI فعال، کمک پیش از تثبیت سؤال و در deadline محدود اعمال می‌شود؛ سؤال نمایش‌داده‌شده هنگام تایپ جابه‌جا نمی‌شود. دادهٔ بیان سؤال فقط descriptorهای مجاز است و مقادیر شخصی ندارد.

**Status:** in-progress

**External prerequisites:** طبق یادداشت آماده‌سازی ۱۷ اکتبر، درگاه kooch، endpoint نمایشی /v1، ماشین‌یوزر و مدل Qwen3.5-35B-A3B موجودند؛ GET مدل‌ها موفق بوده، ولی inference، قیمت، JSON Schema و محدودبودن مجوز کلید هنوز پذیرفته نشده‌اند. سقف اولیه صفر بود؛ مالک در ادامهٔ اجرای ۱۸ اکتبر **۵۰ هزار تومان برای مجموع آزمون و مصرف ماهانهٔ این مرحله** و بررسی خواندنی پنل را تأیید کرد. سقف جداگانهٔ دیگری برای smoke افزوده نشده است. تعرفه در بازارچه پیدا شد، اما IAM محدود، هدر و قابلیت واقعی هنوز پذیرفته نشده‌اند؛ صرف سقف مثبت تولید را فعال نمی‌کند. ساخت دوبارهٔ درگاه یا کلید لازم نیست.

## پذیرش الف — آماده‌سازی بدون هزینهٔ مدل

- [ ] پروفایل اتصال از درگاه موجود استخراج شود: base URL دقیق، مسیر API، شیوهٔ header، شناسهٔ مدل، محدودیت‌ها و نسخهٔ قرارداد؛ فقط تنظیمات غیرمحرمانه ثبت شوند. مستند فعلی مسیر chat/completions را نشان می‌دهد؛ Responses API و تمام قابلیت‌های SDK فرض نشوند.
- [ ] header احراز هویت بر اساس قرارداد endpoint تأیید شود؛ نمونه‌های رسمی curl و SDK شکل متفاوتی دارند و Bearer/Apikey بدون آزمون قرارداد انتخاب نشود. HTTP client retry پیش‌فرض خاموش باشد.
- [ ] دامنهٔ دسترسی ماشین‌یوزرِ موجود فقط برای مدل/منبع لازم بررسی شود. GET مدل‌ها اثبات مجوز تولید پاسخ یا جداسازی منابع نیست؛ مشکل نبود نقش AI در پنل با گسترش دسترسی به کل میزکار حل نشود.
- [x] taskهای question-wording و answer-interpretation نگاشت جدا به پروفایل قابلیت/مدل داشته باشند؛ در نسخهٔ اول فقط همان مدلِ پذیرفته‌شده فعال شود. تغییر مدل/alias/مسیرِ پشت گیت‌وی پذیرش قبلی را خودکار به ارث نبرد.
- [x] فقط سرور مجاز به خواندن کلید باشد؛ endpoint/مدل از ورودی کاربر پذیرفته نشوند. redirect به میزبان دیگر با credential دنبال نشود. شبکهٔ مرورگر مستقیماً به آروان وصل نشود.
- [x] validator برنامه حتی با JSON Schema سمت provider اجباری باشد؛ پاسخ متن ساده/ناقص، reasoning جدا، tool call، refusal، خروجی بریده و شناسهٔ جعلی کنترل شوند. نداشتن قابلیت یک task همان task را خاموش نگه دارد.
- [x] بودجهٔ صفر پیش از هر اتصال تولید پاسخ enforce شود؛ transport در این وضعیت صفر بار صدا زده شود. وضعیت «مدل فهرست شده» از «تولید پاسخ پذیرفته‌شده» جدا نمایش یابد.
- [x] تست گردش‌کار نشان دهد پس از ثبت پاسخ، بدون دکمهٔ کمک سؤال بعدی نمایش داده می‌شود؛ صفر بودجه/خطا/تأخیر فرم را متوقف نکند و سؤال ظاهرشده بعداً با پاسخ مدل تعویض نشود.

## پذیرش ب — فعال‌سازی پس از تعیین بودجه

- [ ] آزمون مصنوعی کم‌حجم روی endpoint واقعی، از سرور محل انتشار، با سقف مشخص؛ نتیجهٔ قابلیت، کیفیت فارسی، تأخیر، مصرف و علت شکست ثبت شود. نمونهٔ آماده‌سازی موجود جای این پذیرش را نگیرد.
- [ ] قیمت با واحد روشن ارز و مقیاس توکن، نسخه/تاریخ تعرفه، محدودیت خروجی و حد بالای هزینهٔ هر task ثبت شود؛ تعرفهٔ نامعلوم مسیر تولید را خاموش نگه دارد.
- [x] برای هر request رزرو اتمیک پیش از ارسال، تسویهٔ usage واقعی و جلوگیری از دوباره‌پرداختن وجود داشته باشد. timeout یا قطع اتصال پس از ارسال «نامعلوم» باشد، نه رایگان؛ رزرو تا تطبیق یا رسیدگی محفوظ بماند. usage غایب صفر نشود.
- [x] سقف روزانهٔ کاربر و سقف سراسری مستقل از rate limit آروان باشند؛ ۱ درخواست در ۵ دقیقهٔ ثبت‌شده در آماده‌سازی، بودجهٔ ماهانه یا ظرفیت فرم عمومی نیست. سهمیه روی قطب‌نما و پاسخ ثابت اثر نگذارد.
- [ ] در ۴۰۱/۴۰۳، ۴۲۹، خطای gateway/upstream و timeout، درخواست پنهانی به مدل دیگر یا provider مستقیم انجام نشود؛ SDK، gateway و اپ retry چندلایه یا fan-out نسازند. Retry-After در صورت وجود فقط برای درخواست تازهٔ مجاز لحاظ شود؛ صف تولید عمومی طولانی ساخته نشود.
- [x] زمان کل کمک سؤال حداکثر ۸ ثانیه و سپس فرم ثابت؛ تغییر مدل یا دسترسی به مدل جایگزین نیازمند پذیرش همان قابلیت و گیرندهٔ داده باشد.
- [x] فقط descriptorهای مجاز هم‌اولویت برای بیان سؤال ارسال شوند؛ مقدار پروفایل، تاریخچهٔ کامل، ایمیل و شناسهٔ حساب ارسال نشوند. نتیجهٔ دیررس به revision جدید اعمال نشود.
- [x] متن خام درخواست/پاسخ در log اپ نباشد؛ مدلِ درخواستی/گزارش‌شده، نسخهٔ سیاست، وضعیت فنی، latency و usage بدون هویت ثبت شوند. ادعای عدم نگهداری تاریخچه از سیاست متریک/log و ارائه‌دهندهٔ بالادست تفکیک شود.

## ارتباط با پایگاه دانش

تیکت ۱۱ انجام شده و بازیابی عمومیِ خودمیزبان مستقل است. برای بیان سؤال، متن ثابت قرارداد کافی است؛ ۱۱ blocker تیکت ۰۵ نیست. اگر بعداً توضیح راهنمای محصول با مدل ارائه شود، فقط قطعه‌های محدود و نسخه‌دار بازیابی‌شده ارسال و شناسهٔ ارجاع خروجی اعتبارسنجی شوند؛ بدون پوشش، پاسخ ساختگی تولید نشود. ساخت KB آروان، embedding یا ارسال پرونده در دامنه نیست. تولید راهنمای آزادِ کاربرمحور در این تیکت اضافه نمی‌شود.

## معیارهای مشترک

- [x] گزینه، قاعده، واحد، نوع کنترل، لینک، کد و HTML اختراعی رد شوند؛ خروجی دیررس پس از تغییر revision کنار گذاشته شود.
- [ ] گاردریل provider در صورت استفاده یک لایهٔ مکمل باشد؛ تغییر آن با همان آزمون‌ها سنجیده شود و تنظیم جدید پنل در این تیکت بدون بررسی اثر فعال نشود. قالب ثابت و اعتبارسنجی اپ به آن وابسته نباشند.
- [x] سقف پیشنهادی ۲۰ فراخوانی موفق روزانه پس از اندازه‌گیری قابل تنظیم باشد؛ تعداد فراخوانی موفق جای سقف هزینه و رزرو درخواست‌های نامعلوم را نگیرد.
- [ ] آزمون پذیرش نسخهٔ مدل/پرامپت/قرارداد با فارسی، امتناع، اختراع، JSON نامعتبر، تأخیر و سقف؛ متن شخصی در log نباشد.

بازنگری برنامه در ۱۷ اکتبر ۲۰۲۶؛ این بازنگری اتصال runtime یا مصرف پولی را فعال نکرد. منابع: یادداشت آماده‌سازی درگاه و پژوهش رسمی در پروندهٔ برنامه.


## اجرای آماده‌سازی — ۱۸ اکتبر ۲۰۲۶، مرحلهٔ تاریخی 81736fc

وضعیت in-progress است؛ پذیرش الف به علت هدر واقعی و IAM محدود کامل نیست و بخش ب فعال نشده است. پروفایل غیرمحرمانه از شواهد موجود استخراج شد؛ مشاهدهٔ تازهٔ پنل یا فهرست مدل‌ها ادعا نمی‌شود. هدر، تعرفه و دو قابلیت هنوز unaccepted/unverified هستند. هیچ کلید/بودجه/مدل واقعی بارگذاری یا تغییر نکرد و هیچ inference اجرا نشد.

در کد، مسیر بودجهٔ صفر پیش از transport بسته است و API فرم وضعیت آن را جدا از فهرست‌شدن مدل اعلام می‌کند. شبیه‌سازی credential ندارد و تنها به میزبان رزروشدهٔ .invalid درخواست می‌سازد. مدل شبیه‌سازی‌شده شناسهٔ یکی از بیان‌های ازپیش‌نوشته‌شده را انتخاب می‌کند؛ متن آزادِ تازه و شخصی‌سازی بر اساس مقادیر پروفایل در این برش پیاده نشده‌اند. validator، deadline/لغو stream، عدم retry، نبود usage و کنترل revision/خروج از حساب آزموده شدند. جزئیات و حدود پذیرش: `apps/kooch/docs/question-assistance.md`.

بررسی‌ها: ۵۸ آزمون اپ با Auth/PostgreSQL واقعی محلی و بدون skip، ۳۸۴ آزمون ریشه، ۴۷ آزمون Python، TypeScript، build، verify:release و check:static موفق شدند. آزمون‌های اولیهٔ بودجهٔ صفر، سؤال خودکار، پاسخ دیررس و لغو بدنه ابتدا شکست خوردند و سپس پاس شدند. انتشار، migration و آزمون inference از سرور انتشار انجام نشده‌اند. در آن مرحله رزرو/تسویهٔ هزینه و سهمیه‌های مثبت هنوز پیاده نشده بود؛ این بخش در مرحلهٔ بعدی همین فایل تکمیل شد.


## تکمیل توسعهٔ کنترل مصرف — ۱۸ اکتبر ۲۰۲۶

مالک در همین گفتگو سقف «فعلاً ۵۰ هزار تومان» و دسترسی خواندنی پنل را تأیید کرد. تصمیم بودجهٔ صفرِ بخش تاریخی بالا با سقف مشترک ۵۰۰٬۰۰۰ ریال جایگزین شد؛ فعال‌سازی همچنان به پذیرش معتبر وابسته است. تعرفهٔ بازارچه برای Qwen3.5-35B-A3B در هر دو جهت ۴٬۲۰۰٬۰۰۰ ریال / یک میلیون توکن دیده شد و با اعتبار محلی ۲۴ ساعت در `data/ai-gateway-policy.json` ثبت شد. جزئیات rounding/invoice هنوز پذیرش زنده نیستند. با کران ورودی اپ ۴۰۹۶ و خروجی ۱۲۸، رزرو محافظه‌کارانه ۱۷٬۷۴۲ ریال است.

کد sender سمت سرور، gate fingerprint/expiry، خواندن مشروط credential، سقف‌های مستقل، دفتر PostgreSQL مشترک، idempotency، تسویهٔ usage واقعی، نگهداری رزرو نامعلوم، توقف در اضافه‌هزینه/۴۰۱/۴۰۳، Retry-After بدون retry، کنترل revision پیش از ارسال و پس از دریافت، metadata بدون متن خام، export/حذف پیوند مالک و پاک‌سازی ۹۰روزه پیاده شدند. migration 004 و متن تازهٔ job فقط محلی آزموده شده‌اند. تیک‌های بخش ب برای این کنترل‌ها به معنی پذیرش production نیستند.

مانع خارجی بازتولید شد: kooch-ai قانون دسترسی متصل ندارد؛ در منبع اختصاصی، فهرست نقش خالی است و در گروه kooch-ai-only جست‌وجوی فارسی/انگلیسی نقش AI نتیجه ندارد. فرم‌های بررسی با انصراف بسته شدند. دسترسی کل میزکار اعطا نشد. [شواهد و سؤال‌های لازم برای سرویس](../../../docs/research/arvan-activation-2026-10-18.md). تا رفع IAM و پذیرش هدر/retry/capability از سرور انتشار، تیکت in-progress و تماس تولیدی خاموش می‌ماند. در این نوبت هزینه‌ای مصرف نشد.

تأیید نهایی توسعهٔ این مرحله: ۷۰ آزمون اپ بدون skip، ۳۸۴ آزمون ریشه، ۴۷ Python، TypeScript، build، verify:release و check:static پاس شدند.

بازبینی مستقل دو P2 در رقابت حذف/رزرو و انتقال پذیرش با تغییر نسخه پیدا کرد؛ هر دو با تست شکست‌خورده بازتولید و سپس اصلاح شدند. قفل مالک، درج رزرو پس از حذف را می‌بندد و policy.version داخل fingerprint است. بازبینی مجدد هر دو محور بدون یافتهٔ باز است. بررسی نهایی: ۷۱ آزمون اپ بدون skip، ۳۸۴ ریشه، ۴۷ Python و همهٔ بررسی‌های الزامی/build موفق‌اند. متن [پیگیری پشتیبانی](../arvan-support-request-fa.md) برای تأیید ارسال توسط مالک آماده شد.

## پژوهش تکمیلی و آزمون تشخیصی واقعی — ۱۸ اکتبر

پس از دستور مالک برای استخراج منابع آروان و ادامه، [قرارداد اتصال و نتیجهٔ آزمون](../../../docs/research/arvan-connection-contract-2026-10-18.md) و [تعرفه و تعهدات](../../../docs/research/arvan-billing-and-service-2026-10-18.md) ثبت شدند. GET مدل‌ها و یک POST ساختگی با کلید موجود، هدر apikey و سقف ۱۲۸ توکن هر دو HTTP 200 دادند. POST در ۱۷۶۶ms با usage ورودی۶۵۹/خروجی۱۲۸ برگشت؛ تمام خروجی reasoning و finish_reason=length بود و متن نهایی null ماند. پس اتصال تولید کار می‌کند، ولی تنظیم فعلی پذیرش بیان سؤال را پاس نمی‌کند. هزینهٔ واقعی صفرِ مرحلهٔ قبلی دیگر شامل این probe نیست؛ صورتحساب probe pending است. هیچ retry یا آزمون دوم انجام نشد. این تشخیص محلی، پذیرش از سرور انتشار یا اثبات IAM محدود نیست؛ وضعیت تیکت و production تغییر نکردند.

مالک سپس یک آزمون دوم با وجود صورتحساب نامعلوم و همان سقف مشترک را صریحاً تأیید کرد. با `chat_template_kwargs.enable_thinking=false` همان مدل در۱۲۹۵ms، reasoning صفر و۱۱توکن خروجی نهایی داد؛ پاسخ داخل حصار Markdown بود و هنوز JSON خام معتبر برای اپ نیست. دو فراخوانی تشخیصی مجموعاً۱۴۵۹توکن مصرف کردند؛ صورتحساب نهایی pending است و آزمون سوم اجرا نشد. پارامتر ثابت خاموش‌کردن thinking با تست شکست‌خورده سپس پاس‌شده به درخواست اپ اضافه شد و contract_version به۲ تغییر کرد تا پذیرش قدیمی معتبر نماند. validator شل و gate production فعال نشدند. بازبینی مستقل Standards و Spec هر دو بدون یافته‌اند.
