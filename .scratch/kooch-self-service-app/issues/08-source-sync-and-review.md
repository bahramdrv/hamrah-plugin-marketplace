# 08: به‌روزرسانی داده و بازبینی تغییرات

**What to build:** اپ دادهٔ عمومی کوچ را تازه دریافت می‌کند، تغییر مؤثر بر کارنامه را تشخیص می‌دهد و مدیر وضعیت منقضی یا متعارض را برای بازبینی می‌بیند؛ قطع دریافت نتیجهٔ نادرست نمی‌سازد.

**Blocked by:** 01 — قطب‌نمای فارسی و فهرست مستند؛ 04 — نخستین کارنامهٔ مقدماتی واقعی.

**Status:** done

- [x] قرارداد نسخه‌دار عمومی برای هویت، page_url، snapshot، منبع و freshness و قواعد نگاشت؛ دادهٔ خصوصی وارد آن نشود.
- [x] همهٔ صفحه‌های یک برداشت به یک نسخهٔ سازگار متصل باشند؛ برداشت نیمه‌تمام فعال نشود.
- [x] دریافت محدود به endpoint مجاز با timeout، حد اندازه، schema/hash و checkpoint؛ اجرای دوباره و قطع وسط کار امن باشند.
- [x] دریافت موفق Atlas تاریخ تأیید منبع رسمی را تمدید نکند؛ تغییر شروط مؤثر یا تعارض به بازبینی برود و فعال‌سازی قواعد خودکار نباشد.
- [x] در هر match/report انقضا بررسی شود؛ حتی با اجرا نشدن cron، دادهٔ منقضی نتیجهٔ قطعی ندهد و کاتالوگ کامل fallback نشود.
- [x] نسخهٔ سالم در خطای شبکه حفظ شود ولی اعتبارش تمدید نشود؛ گزارش‌های مصرف‌کننده نیازمند بازبینی نشان داده شوند و قبلی‌ها ثابت بمانند.
- [x] مدیر آخرین sync، تعداد دارای پوشش، منقضی‌ها و صف بررسی را ببیند؛ endpoint مدیریت احراز هویت/اختیار مستقل داشته باشد.
- [x] زمان‌بندی با پلن مجاز و بدون خرید سرویس؛ اجرای دستیِ مستند برای بازیابی و تست خرابی/تکرار/انقضا وجود داشته باشد.

مرز آزمون مطابق spec: API ورود دادهٔ عمومی و وضعیت عملیاتی مدیر، همراه با match/report مصرف‌کننده؛ شبکه و ساعت fixture و ذخیره‌سازی PostgreSQL واقعی محلی است. مبنای بازبینی این برش `60e7fae` است.

پذیرش محلی ۲۰۲۶-۱۰-۲۱: ۱۱۱ تست اپ، ۳۸۴ تست مخزن، ۴۷ تست Python، verify:release، check:static و build/typecheck موفق شدند. هر دو بازبینی Standards و Spec پس از اصلاح، بدون یافتهٔ باز هستند. exporter وردپرس محلی ۲ صفحه و ۲۹ مسیر را با hash و تاریخ‌های اصلی به مصرف‌کنندهٔ Node/PostgreSQL تحویل داد. رابط مدیر در دسکتاپ و موبایل ۳۹۰px پذیرفته شد؛ کلید پس از درخواست پاک می‌شود و سرریز افقی ندارد.
