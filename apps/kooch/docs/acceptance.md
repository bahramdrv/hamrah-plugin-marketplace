مالک Supabase Free را برای Auth و PostgreSQL انتخاب کرد؛ SMTP جدا تعیین می‌شود. پیاده‌سازی محلی با PostgreSQL واقعی، Supabase Auth رسمی و تحویل SMTP به Mailpit آزموده شد. پروژهٔ Supabase میزبان، SMTP عمومی و زمان‌بندی پاک‌سازی میزبان هنوز متصل نیستند؛ تیکت در حال انجام است.

TypeScript و build تولید موفق بودند؛ ۳۸۴ آزمون اصلی Node، verify:release، check:static و ۴۷ آزمون Python نیز پاس شدند. جست‌وجوی مقدار واقعی رازهای سرور در فایل‌های JavaScript مرورگر صفر تطبیق داشت. فایل‌های محیطی خارج Git هستند.

مرورگر داخلی روی build تولید و حساب کاملاً ساختگی: نتیجه پیش از ورود، رضایت مستقل و ذخیرهٔ نسخهٔ ۱، ادامهٔ همان پرونده و اصلاح به نسخهٔ ۲ تأیید شدند. خروج از تب دوم، پاسخ‌های خصوصی تب اول را پاک کرد. صفحهٔ حساب در ۱۴۴۰×۹۰۰ و ۳۶۰×۸۰۰ بررسی شد؛ عرض محتوا در موبایل ۳۶۰ و جهت rtl بود. تصاویر account-desktop.png و account-mobile.png در پوشهٔ شواهد محلی با view_image بررسی شدند؛ فرم و راهنما در موبایل یک‌ستون و بدون سرریز هستند.

Site URL روی https://my.kooch.app/account ثبت شد؛ Confirm email فعال است و Minimum password length با پیام Successfully updated settings به ۱۲ تغییر کرد. Data API خاموش است. Resend و Vercel هنوز نشست واردشده ندارند. دامنهٔ my هنگام مراجعه ERR_NAME_NOT_RESOLVED داد؛ NS دامنه kooch.app روی limoodns.com است. قالب ایمیل میزبان تا اتصال SMTP سفارشی قابل ویرایش نیست. هیچ ایمیل عمومی یا انتشار نهایی در این مرحله آزموده/ادعا نشده است.

پشتیبانی کلید جدید sb_secret با دو آزمون مرز REST (شکست اولیه و سپس عبور) افزوده شد. ۱۹ آزمون بدون شبکهٔ اپ، TypeScript و build موفق شدند؛ ۷ آزمون یکپارچهٔ نیازمند Docker در این اجرا skip شدند زیرا daemon خاموش است و راه‌اندازی UI مجوز ندارد. آزمون‌های HTTP مخزن ابتدا با listen EPERM شکست خوردند و با دسترسی localhost هر ۳۸۴ آزمون پاس شدند. verify:release، check:static و ۴۷ آزمون Python نیز پاس شدند.

## تیکت ۰۴ — کارنامه در جریان مشترک، ۱۷ اکتبر ۲۰۲۶

مدل محصول یک پرونده، یک پرسش‌نامه و یک کارنامهٔ قابل گسترش به چند مسیر است. ماژول نخست uk:student است؛ کاربر وارد فرم مستقل کشور نمی‌شود. سن، تحصیل، زبان و بودجه از همان پاسخ‌های پرونده می‌آیند؛ سؤال‌های تکمیلی لازم در /form، با نسخه و منشأ خوداظهاری و وابستگی، یک‌به‌یک ادامه می‌یابند. /report فقط ساخت/نمایش از پاسخ‌های ذخیره‌شده دارد؛ POST facts اضافی را رد می‌کند. snapshot یک envelope با route_results و نسخهٔ پرونده است. برای هدف/مقصد فاقد ماژول، نبود پوشش به‌جای نتیجهٔ بریتانیا نمایش داده می‌شود.

منابع اولیهٔ GOV.UK در ۱۷ اکتبر بررسی و سیاست نسخه‌دار با URL/تاریخ/انقضا در guidance-report.md نگاشت شد. تاریخ مؤثر نامعلوم null است؛ استفاده فقط برنامه‌ریزی جاری را پوشش می‌دهد و تاریخ هدف خارج بازه needs_review می‌شود. مدارک تأیید نمی‌شوند، پوشش partial است و نتیجه رسمی یا احتمال/نمره ساخته نمی‌شود. تمکن، هزینهٔ دولتی، نرخ سالانهٔ IHS و همراه جدا هستند؛ کل IHS، مدت اجازهٔ اقامت همراه، ترجمه و سفر نامعلوم می‌مانند. ارز تبدیل حدسی ندارد.

آزمون API با Auth/PostgreSQL واقعی و دادهٔ مصنوعی: ناقص، کامل، شرط نامحقق، تعارض، انقضا، تقویم شش‌ماهه/۲۸/۳۱ روز، مالکیت، revision، retry هم‌زمان، snapshot ثابت، export و حذف پاس شدند. ابتدا نبود report endpoint، سپس ورودی قواعد، مرز پایان ماه، مبلغ همراه، ورود قواعد حقوقی به KB و وابستگی نگهداری وجه red شدند؛ پس از اصلاح green. تاریخ هدف و شواهد منقضی نتیجهٔ قطعی تازه نمی‌سازند. نقش app گزارش را UPDATE نمی‌کند؛ حذف پرونده CASCADE است. ساخت تازه نگهداری را تمدید و retry/خواندن ثابت نگه می‌دارند. اجرای فایل‌های آزمون ترتیبی است چون تست purge با ساعت آینده یک DB مشترک را پاک می‌کند؛ concurrency داخل سناریوی retry حفظ است.

مرورگر روی build تولید localhost:3114: همان حساب ساختگی و پرونده، بازبینی نگهداری وجه پس از تغییر محل، تأیید روزها/تاریخ، خلاصهٔ پاسخ‌ها، پیوند به کارنامه و ساخت نسخهٔ ۱ از revision ۲۵ بدون دریافت ورودی دوباره مشاهده شدند. تمکن بیرون لندن با مثال مصنوعی ۲۴۵۳۹ GBP از هزینهٔ مصرفی جدا بود. ## آماده‌سازی بدون هزینهٔ تیکت ۰۵ — ۱۸ اکتبر ۲۰۲۶

API فرم، بعد از ثبت پاسخ سؤال بعدی را خودکار با وضعیت budget_zero برمی‌گرداند؛ transport در این حالت صفر بار صدا زده می‌شود. اتصال تولیدی واقعی و خواندن کلید خصوصی وجود ندارد. دو قابلیت بیان سؤال/تفسیر پاسخ جدا و پذیرش‌نشده‌اند. رابط غیرفعال‌بودن کمک هوشمند را اعلام می‌کند.

transport ساختگیِ بدون credential روی میزبان .invalid، بیان فارسی مجاز، حداقل descriptor بدون مقادیر پرونده، تک‌ارسال بدون retry/redirect، مهلت شامل بدنه، لغو stream، JSON/usage/مدل/شناسه معتبر و رد اختراع، reasoning، ابزار، refusal و خروجی بریده را می‌سنجد. API واقعی محلی رقابت revision و خروج هنگام تأخیر را پوشش می‌دهد. سؤال ظاهرشده callback برای تعویض هنگام تایپ ندارد؛ پاسخ دیررس با همان revision به رابط تزریق نمی‌شود. آزمون زندهٔ مدل یا بررسی تازهٔ مرورگر در این برش انجام نشده است.

نتیجه: هر ۵۸ آزمون اپ با سرویس‌های واقعی محلی و بدون skip، ۳۸۴ آزمون ریشه، ۴۷ Python، TypeScript، build، verify:release و check:static موفق‌اند. تیکت باز می‌ماند: قرارداد هدر و IAM، تعرفه و کنترل اتمیک هزینه، کیفیت/قابلیت مدل و smoke از سرور انتشار هنوز پذیرش نشده‌اند. هیچ هزینه، انتشار یا تغییری در خدمات میزبانی ایجاد نشد. مرز دقیق پیاده‌سازی و موارد باقی‌مانده در [راهنمای بیان سؤال](question-assistance.md) ثبت است.


## تکمیل محلی اتصال و سقف مصرف تیکت ۰۵ — ۱۸ اکتبر ۲۰۲۶

پس از دستور ادامه تا انتها، مالک سقف مشترک ۵۰ هزار تومان برای آزمون و مصرف ماهانهٔ این مرحله و بررسی خواندنی پنل را تأیید کرد. سقف واحد ۵۰۰٬۰۰۰ ریال در سیاست نسخه‌دار ثبت شد؛ سهم مستقلِ اضافی برای smoke ایجاد نشد. نرخ نمایشی بازارچه در هر دو جهت ۴٬۲۰۰٬۰۰۰ ریال/میلیون توکن است؛ شمول همهٔ هزینه‌های invoice هنوز تأیید نشده و gate خاموش می‌ماند.

sender واقعی پشت gate قیمت/پذیرش/IAM/header، fingerprint اتصال و تاریخ انقضا قرار دارد. قبل از dispatch، ledger PostgreSQL واقعی سقف‌های ماهانه/روزانهٔ مشترک و روزانهٔ کاربر را اتمیک رزرو می‌کند. دو instance، idempotency، دو مالک، پایان سهمیه و ادامهٔ فرم، usage واقعیِ متن نامعتبر، timeout/نبود usage، عبور از نیمه‌شب، تسویهٔ تکراری، تعرفهٔ تاریخی، اضافه‌هزینه، ۴۰۱/۴۰۳/۴۲۹ و Retry-After، مهلت شامل صف DB و جلوگیری از ارسال پس از آن آزموده شدند. هیچ transport واقعی مدل در آزمون‌ها وجود ندارد.

شناسهٔ مالی تصادفی از پیوندهای مالک/idempotency جداست؛ export دادهٔ همان مالک را می‌دهد و حذف حساب هر دو پیوند را پاک می‌کند. پاک‌سازی محدود ۹۰روزهٔ metadata، رزرو نامعلوم و breaker را بدون پیوند مالک حفظ می‌کند. migration 004 فقط روی PostgreSQL آزمایشی نصب شد؛ job میزبانی تغییر نکرد. TypeScript، build و هر ۷۰ آزمون اپ بدون skip، ۳۸۴ آزمون ریشه، ۴۷ Python، verify:release و check:static موفق شدند؛ پس از اصلاح پیوندها، سناریوهای مالی/حذف دوباره پاس شدند.

پذیرش خارجی بسته نشده است: بررسی زنده نشان داد ماشین‌یوزر kooch-ai قانون متصل ندارد؛ انتخاب نقش AI برای منبع اختصاصی خالی است و جست‌وجوی نقش در گروه نتیجه ندارد. هیچ تغییر IAM، credential یا خدمات ایجاد نشد. درخواست تولید واقعی، هزینه و عرضه انجام نشدند. هدر، IAM محدود، رفتار retry درگاه، صورتحساب کامل و قابلیت/فارسی/latency از سرور انتشار هنوز باقی‌اند. جزئیات شاهدها در [بررسی زندهٔ آروان](../../../docs/research/arvan-activation-2026-10-18.md) و رفتار کد در [بیان سؤال](question-assistance.md) ثبت‌اند؛ وضعیت تیکت in-progress است.


بازبینی مستقل همین مرحله دو P2 یافت: درج رزرو پس از حذف مالک و عبور از breaker با تغییر صرف نسخه. هر دو ابتدا با تست بازتولید شدند و با قفل ردیف مالک داخل تراکنش رزرو و افزودن نسخه به fingerprint رفع شدند. بازبین‌های Standards و Spec رفع را تأیید کردند و یافتهٔ بازی ندارند. بررسی نهایی پس از اصلاح: ۷۱ آزمون اپ بدون skip، ۳۸۴ ریشه، ۴۷ Python، TypeScript، build، verify:release و check:static موفق‌اند. متن پیگیری پشتیبانی آماده است؛ هنگام ثبت این پذیرش هنوز ارسال نشده است.
# پذیرش برش خاموش‌کردن thinking — ۱۸ اکتبر ۲۰۲۶

یک آزمون تشخیصی دوم با تأیید صریح مالک، پارامتر `chat_template_kwargs.enable_thinking=false` را روی مدل فعلی سنجید: HTTP200، reasoning صفر، خروجی۱۱توکن و۱۲۹۵ms. متن داخل حصار Markdown بود و برای قرارداد JSON خام اپ پذیرفته نیست. این شاهد از پذیرش production جداست؛ محدودیت IAM/صورتحساب/سرور انتشار و پذیرش پرامپت واقعی هنوز بازند.

پارامتر با red→green در seam کمک سؤال اضافه شد؛ نسخهٔ قرارداد۲ است و تست درگاه، پذیرش قرارداد۱ را پیش از خواندن کلید رد می‌کند. fenced JSON همچنان رد می‌شود. بررسی نهایی:۷۲ تست اپ بدون skip،۳۸۴ تست ریشه،۴۷ Python، typecheck، build، verify:release و check:static موفق‌اند. اجرای اولیهٔ تست‌های ریشه به‌دلیل منع listen روی localhost در sandbox شکست خورد؛ اجرای مجدد با دسترسی localhost همه را پاس کرد. هر دو بازبینی Standards/Spec بدون یافته‌اند. هیچ push، deploy یا فراخوانی پولی سوم انجام نشد.

## پذیرش metadata خالی — ادامهٔ همان روز

با مجوز صریح آزمون سوم، پرامپت واقعی app پاسخ JSON خام انتخاب مجاز در۱۳۱۱ms و reasoning صفر داد؛ validator پیشین extra metadata را رد کرد. اصلاح قرارداد۳ تنها nullهای مشخص و annotations=[] را مجاز می‌داند و metadata غیرخالی، کلید ناشناخته و Markdown را رد می‌کند. تست ابتدا شکست و پس از اصلاح پاس شد؛ integration متری‌شده، تسویه و همان envelope خالی را بررسی می‌کند. نسخه‌های۱/۲ پیش از کلید رد می‌شوند. مقادیر کامل metadata پاسخ واقعی نگه‌داری نشده‌اند؛ از replay محلی نمی‌توان پذیرش live پاسخ اصلی را نتیجه گرفت.

## پذیرش null در annotations — ادامهٔ بستهٔ مجاز

بستهٔ max3/stop-first-failure با مجوز صریح اجرا شد؛ تنها سؤال سن ارسال و سپس به‌دلیل annotations=null متوقف شد. قرارداد۴ همین نمایش خالی را همراه [] می‌پذیرد؛ null ابتدا تست را شکست داد و سپس پاس شد. متادیتای غیرخالی و کلید ناشناخته همچنان ردند؛ integration متری‌شده null و رد قراردادهای۱/۲/۳ را می‌سنجد. بازسازی آفلاین حداقل envelope با تطبیق hashمتن پاس شد، اما roleassistant در آن قرار داده شده و پذیرش live دوباره نیست.

بررسی نهایی همین برش:۷۳تست اپ بدون skip،۳۸۴ریشه،۴۷Python،typecheck/build/release/static موفق؛ Standards وSpec بدون یافته. دو درخواست باقیماندهٔ بسته اجرا نشدند. هیچ push،deploy یا فعال‌کردن production انجام نشد.
