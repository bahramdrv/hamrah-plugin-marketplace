# پذیرش تیکت ۰۱ — ۱۵ اکتبر ۲۰۲۶

- اپ مستقل: `apps/kooch`؛ Node 22، قفل npm، Next.js 16.4.1 و React 19.3.1. راه‌اندازی و `next build` موفق؛ مسیرهای `/api/config` و `/api/compass` پویا هستند.
- ۱۳ آزمون API/ورود داده: scope ایران، هدف، CEC/PGWP و سابقه، بسته/داخل مقصد، انقضا، صفر نتیجه، شمار متغیر، لینک واقعی، ورودی محدود، بودجهٔ صفر، جدایی مهمان‌ها، حجم و مبدأ، اصلاح پاسخ پیش‌نیاز قبلی و حفظ آخرین snapshot هنگام خطا. شکست اولیهٔ API و adapter قبل از پیاده‌سازی ثبت شد. خطای واقعی مبدأ داخلی Next نیز با آزمون بازتولید اصلاح شد.
- دریافت واقعی از API عمومی با scope ثابت موفق شد؛ فقط دادهٔ عمومی دریافت شد. دریافت دوم با `npm run refresh:data` نیز موفق؛ تاریخ بررسی منابع همان ۱۵ اکتبر و اعتبار همان ۲۹ اکتبر ماند.
- ۳۸۴ آزمون اصلی Node، بررسی انتشار و نحو پاس شدند؛ ۴۷ آزمون Python با `/opt/anaconda3/bin/python3` پاس شدند. Python پیش‌فرض pytest ندارد. دو fixture مهلت ثابت ۱۵/۲۰ اکتبر در آزمون موجود DAAD به مهلت آینده نسبت به زمان اجرا تبدیل شدند؛ کد اجرایی MCP و کار کاربر در آن فایل تغییر داده نشد.
- مرورگر داخلی Codex روی production build: پیمایش هشت گام با پاسخ ساختگی تحصیل/آلمان، ارقام فارسی `۱۵٬۰۰۰`، سؤال شرطی پذیرش، یک نتیجه با `student-de-catalog`، برگشت و حفظ پاسخ، بازیابی پیش‌نویس پس از reload و پاک‌کردن پاسخ‌ها تأیید شدند. پاسخ‌های آزمایشی شخص واقعی نبودند. پس از بازبینی، تغییر پذیرش آلمان از بله به خیر و بازگشت به بله بدون پاک‌کردن پاسخ‌های پایه نیز در مرورگر تأیید شد.
- عرض ۱۴۴۰×۹۰۰ و موبایل ۳۶۰×۸۰۰ بررسی شد. در موبایل `scrollWidth=innerWidth=360`، زبان `fa` و جهت `rtl` تأیید شدند. تصویر viewport استفاده شد؛ ثبت full-page مرورگر داخلی در RTL تصویر را می‌برید و برای ارزیابی استفاده نشد.
- طرح و تصویر آخر با `view_image` مقایسه شدند: زمینهٔ سفید، رنگ و مرز گزینهٔ انتخابی، سلسله‌مراتب قلم فارسی، فرم راست/راهنمای چپ، نوار سه‌مرحله‌ای، دکمه‌ها و تک‌ستون موبایل بررسی شدند. برای عرض میانی، ستون راهنما که باریک می‌شد به زیر فرم منتقل شد. تطبیق ساختار و سبک مرجع تأیید شد؛ متن قانونی و دادهٔ تصویر نمونه با قرارداد واقعی جایگزین شدند، و دو هدف مصوب به گزینه‌ها اضافه شدند. مغایرت بصری مهم شناخته‌شده باقی نماند.

تصویرهای محلی مرورگر در `.scratch/kooch-self-service-app/evidence/` هستند: `form-desktop.png`، `form-mobile.png`، `result-desktop.png` و `result-mobile.png`. جریان اصلی و متن آغاز با موارد مجاز طراحی کنترل شدند؛ تفاوت‌های متن عمدی در بالا ثبت شده‌اند.

انتشار عمومی، حساب، پایگاه داده، AI، اتصال DNS یا پلن پولی ایجاد نشد. این نتیجه فهرست مسیر برای بررسی است؛ ارزیابی تمام شروط یا کارنامهٔ نهایی نیست.

بازبینی مستقل Standards: صفر نقض مستند، یک پیشنهاد غیرمسدودکننده برای جمع‌کردن حلقهٔ خواندن محدود stream در API و adapter. بازبینی Spec: یک P2 در ویرایش پاسخ‌های پیش‌نیاز یافت شد؛ مجموعهٔ سؤال‌های قابل ویرایش از سؤال‌های بی‌پاسخ جدا و مسیر اصلاح مستقل افزوده شد. بازبینی مجدد Spec مانع باقی‌مانده‌ای پیدا نکرد.

## بازخورد کارت و نتیجهٔ خالی — ۱۵ اکتبر ۲۰۲۶

علت بازتولیدشده در API: فیلتر قبلی فقط مسیرهایی را نشان می‌داد که همهٔ پاسخ‌های پیش‌نیازشان بله بود؛ حتی پذیرش و پیشنهاد کار به دروازهٔ نمایش تبدیل شده بودند. آزمون تحصیل آلمان بدون پذیرش ابتدا شکست خورد و پس از تفکیک پیش‌نیاز آماده‌کردنی از سابقهٔ لازم پاس شد. اکنون بدون پذیرش یا پیشنهاد کار، مسیر مرتبط همراه گام آماده‌سازی نمایش می‌یابد؛ CEC/PGWP بدون سابقهٔ لازم کانادا و HPI بدون مدرک مشمول پیشنهاد مستقیم نیستند. نبود رابطهٔ خانوادگی همچنان مانع نمایش مسیر خانوادگی است.

۱۶ آزمون API و دریافت داده، TypeScript و build موفق‌اند. نمونه‌های هدف/مقصد: کار/آلمان ۲، تحصیل/آلمان ۱، خانواده/کانادا ۱، کارآفرینی/بریتانیا ۱، سرمایه/پرتغال ۱ و تحصیل/پرتغال صفر مسیر. حقایق منقضی از کارت حذف می‌شوند؛ دریافت تازهٔ کاتالوگ خلاصه و حقایق بازبینی‌شده را جایگزین نمی‌کند.

خلاصه و حقایق کارت از راهنمای موجود `iran-route-guides.json` با پیوند منبع اولیه و تاریخ واقعی همان منبع وارد نسخهٔ ۲ snapshot شدند. تاریخ‌ها تمدید نشدند. جزئیات منابع و تاریخ فقط در بخش بازشدنی هستند. تغییرات به دادهٔ منتشرشدهٔ کامیونیتی دست نمی‌زنند.

مرورگر داخلی با نشست آزمایشی جدا: فقط انتخاب تحصیل، بدون پاسخ تکمیلی، چهار کارت واقعی کانادا/آلمان/ایتالیا/بریتانیا داد؛ بدنهٔ کارت شامل خلاصه، شروط/مبالغ مستند، روش اقدام و گام بعد بود. در موبایل ۳۶۰×۸۰۰ سرریز افقی وجود نداشت و جزئیات منابع بسته بودند. تصاویر `feedback-cards-desktop.png` و `feedback-cards-mobile.png` در پوشهٔ شواهد محلی‌اند.

بازبینی بازخورد: Standards صفر نقض و صفر پیشنهاد تازه؛ Spec یک regression در دریافت سؤال‌های سابقهٔ کانادا پیدا کرد که با جداسازی مجموعهٔ سؤال‌های لازم از مجموعهٔ مسیرهای قابل نمایش، و آزمون red→green رفع شد. بازبینی مجدد مانعی نیافت. ۳۸۴ آزمون اصلی Node، ۴۷ آزمون Python، verify:release و check:static نیز پاس شدند.

## پذیرش محلی تیکت ۰۲ — ۱۵ اکتبر ۲۰۲۶

مالک Supabase Free را برای Auth و PostgreSQL انتخاب کرد؛ SMTP جدا تعیین می‌شود. پیاده‌سازی محلی با PostgreSQL واقعی، Supabase Auth رسمی و تحویل SMTP به Mailpit آزموده شد. پروژهٔ Supabase میزبان، SMTP عمومی و زمان‌بندی پاک‌سازی میزبان هنوز متصل نیستند؛ تیکت در حال انجام است.

۲۴ آزمون اپ بدون skip پاس شدند: ۱۶ آزمون قطب‌نما، ۷ آزمون یکپارچهٔ حساب و یک آزمون پاسخ دیررس مرورگر. پوشش حساب شامل تأیید و بازیابی یک‌بارمصرف، نشست بازیابی پس از reload، انتقال فقط با رضایت، دو مالک مستقل، RLS واقعی با نقش محدود، export، حذف و تکرار پس از خطای provider، CSRF، no-store، انقضا، لغو نشست، رقابت revision و idempotency است. آزمون نشست بازیابی و پاسخ دیررس ابتدا شکست خوردند و با اصلاح رفتار پاس شدند.

TypeScript و build تولید موفق بودند؛ ۳۸۴ آزمون اصلی Node، verify:release، check:static و ۴۷ آزمون Python نیز پاس شدند. جست‌وجوی مقدار واقعی رازهای سرور در فایل‌های JavaScript مرورگر صفر تطبیق داشت. فایل‌های محیطی خارج Git هستند.

مرورگر داخلی روی build تولید و حساب کاملاً ساختگی: نتیجه پیش از ورود، رضایت مستقل و ذخیرهٔ نسخهٔ ۱، ادامهٔ همان پرونده و اصلاح به نسخهٔ ۲ تأیید شدند. خروج از تب دوم، پاسخ‌های خصوصی تب اول را پاک کرد. صفحهٔ حساب در ۱۴۴۰×۹۰۰ و ۳۶۰×۸۰۰ بررسی شد؛ عرض محتوا در موبایل ۳۶۰ و جهت rtl بود. تصاویر account-desktop.png و account-mobile.png در پوشهٔ شواهد محلی با view_image بررسی شدند؛ فرم و راهنما در موبایل یک‌ستون و بدون سرریز هستند.

بازبینی مستقل Standards و Spec انجام شد. دو ایراد دسترسی به پاسخ دیررس پس از خروج و بازیابی نشست محدود پس از reload رفع شدند؛ بازبینی مجدد هیچ مانع باقی‌مانده‌ای نیافت. تحویل واقعی ایمیل عمومی در این پذیرش ادعا نمی‌شود.

## اتصال اولیهٔ Supabase میزبان — ۱۶ اکتبر ۲۰۲۶

پروژهٔ Free `kooch` در سازمان `Kooch` و منطقهٔ eu-west-1 با وضعیت Healthy تأیید شد. پس از تأیید صریح مالک، اسکریپت schema در SQL Editor اجرا شد و پیام Success برگشت. پرس‌وجوی مستقل پنج جدول، دو سیاست RLS، FORCE RLS روی cases/requests، نقش‌های بدون superuser/BYPASSRLS و عضویت runtime را تأیید کرد. نقش‌های anon/authenticated روی schema خصوصی USAGE ندارند. رمز نقش اپ هنوز unset است و آزمون runtime میزبان انجام نشده است.

Site URL روی https://my.kooch.app/account ثبت شد؛ Confirm email فعال است و Minimum password length با پیام Successfully updated settings به ۱۲ تغییر کرد. Data API خاموش است. Resend و Vercel هنوز نشست واردشده ندارند. دامنهٔ my هنگام مراجعه ERR_NAME_NOT_RESOLVED داد؛ NS دامنه kooch.app روی limoodns.com است. قالب ایمیل میزبان تا اتصال SMTP سفارشی قابل ویرایش نیست. هیچ ایمیل عمومی یا انتشار نهایی در این مرحله آزموده/ادعا نشده است.

پشتیبانی کلید جدید sb_secret با دو آزمون مرز REST (شکست اولیه و سپس عبور) افزوده شد. ۱۹ آزمون بدون شبکهٔ اپ، TypeScript و build موفق شدند؛ ۷ آزمون یکپارچهٔ نیازمند Docker در این اجرا skip شدند زیرا daemon خاموش است و راه‌اندازی UI مجوز ندارد. آزمون‌های HTTP مخزن ابتدا با listen EPERM شکست خوردند و با دسترسی localhost هر ۳۸۴ آزمون پاس شدند. verify:release، check:static و ۴۷ آزمون Python نیز پاس شدند.

بازبینی Standards یک ایراد P2 در اولویت گزینه‌های SSL رشتهٔ اتصال ابزار موقت پیدا کرد؛ ابزار اکنون هر query string را پیش از pg.Client رد می‌کند و target را ثابت می‌سنجد. بازبینی دوباره رفع را تأیید کرد. بازبینی Spec مانعی نیافت. راهنمای موقت اتصال از قالب wizard با کتابخانهٔ بدون تغییر ساخته و با bash -n و node --check بررسی شد؛ هیچ credential واقعی به آن داده نشده و اجرا نشده است.
