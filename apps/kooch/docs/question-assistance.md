# آماده‌سازی بیان سؤال — تیکت ۰۵

۱۸ اکتبر ۲۰۲۶. این برش آماده‌سازی بدون هزینه است. تیکت تا پذیرش خارجی و فعال‌سازی باز می‌ماند.

## اتصال و حدود تأیید

پروفایل غیرمحرمانه در `src/ai/question-assistance.ts`، نسخهٔ `arvan-kooch-preparation-1`، از یادداشت آماده‌سازی ۱۷ اکتبر استخراج شده است: base URL برابر `https://api.arvancloudai.ir/v1`، مسیر پیشنهادی `/chat/completions` و مدل فهرست‌شدهٔ `Qwen3.5-35B-A3B`. مشاهدهٔ GET مدل‌ها مربوط به همان تاریخ است، نه آزمون مجدد امروز. نگاشت‌های `question-wording` و `answer-interpretation` جدا و هر دو unaccepted هستند. تغییر alias/مدل/upstream/قرارداد نیازمند پذیرش تازه است.

[راهنمای HTTP رسمی](https://docs.arvancloud.ir/fa/aiaas/api-usage/) در بازخوانی ۱۸ اکتبر هدر `Authorization: apikey …` را نشان می‌دهد؛ [نمونهٔ SDK](https://docs.arvancloud.ir/fa/aiaas/examples/openai/) پیشوند را در مقدار api_key دارد. قرارداد واقعی gateway هنوز unverified است؛ هدر حدسی وارد runtime نشد. Responses API، JSON Schema، retry و قابلیت دیگری فرض نشده‌اند. دامنهٔ IAM محدود همچنان تأیید نشده است؛ منبع در گروه اختصاصی است، ولی نقش AI طبق آماده‌سازی قبلی قابل انتخاب نبود. کلید/حساب/درگاه تازه و دسترسی گسترده ساخته نشد.

بودجهٔ runtime در این نسخه ثابت و صفر است. هیچ env یا ورودی API آن را مثبت نمی‌کند. factory حتی با transport تزریق‌شده، بدون حالت صریح simulation، صفر بار transport را صدا می‌زند. runtime کلید خصوصی آماده‌سازی را بارگذاری نمی‌کند و sender تولید واقعی ندارد. فعال‌سازی با تغییر یک flag ممکن نیست: تعرفه، رزرو اتمیک مشترک، تسویه و نگهداری هزینهٔ نامعلوم، سهم روزانه/سراسری، پذیرش IAM/هدر/مدل و آزمون مصنوعی محدود از سرور انتشار هنوز باید پیاده و پذیرفته شوند. تعداد موفق روزانه جای این کنترل‌ها نیست.

## رفتار فرم و شبیه‌سازی

API مالک‌دار موجود `/api/account/form` پس از ثبت پاسخ همان سؤال بعدی قطعی را خودکار برمی‌گرداند. statusِ `budget_zero`، وضعیت مدل فهرست‌شده و پذیرش‌نشدن inference/interpretation جدا هستند. رابط غیرفعال‌بودن کمک هوشمند و ادامهٔ فرم ثابت را اعلام می‌کند. گزینهٔ «کمک» یا درخواست مستقیم مرورگر به مدل اضافه نشده است.

transport شبیه‌سازی فقط با dependency injection سمت سرور و به میزبان رزروشدهٔ `https://arvan.invalid/v1/chat/completions` اجرا می‌شود؛ هیچ کلید یا Authorization ندارد و هرگز به endpoint واقعی نمی‌رود. این شبیه‌سازی، پذیرش قرارداد HTTP، کیفیت مدل واقعی یا سقف هزینه نیست. یک ارسال، redirect=error، بدون SDK، retry یا fallback پنهان؛ deadline شامل دریافت header و بدنه حداکثر ۸ ثانیه است. خطا/تأخیر همان سؤال ثابت را حفظ می‌کند. helper آزمون می‌تواند deadline را کوتاه کند، ولی نه از ۸ ثانیه بیشتر.

در این آماده‌سازی، مدل شبیه‌سازی‌شده صرفاً شناسهٔ یک بیان فارسیِ ازپیش‌نوشته‌شده را انتخاب می‌کند؛ تولید متن آزاد پیاده نشده است. برای هفت سؤال عمومی بیان سادهٔ جایگزین داریم؛ دیگر سؤال‌ها تنها بیان اصلی را دارند. ورودی فقط descriptorهای id/version/title/help/priority سؤال بعدی قطعی و فهرست بیان‌های مجاز است. حتی مقادیر غیرشخصی پروفایل، revision، case ID، ایمیل، پاسخ و تاریخچه ارسال نمی‌شوند. کنترل، گزینه، واحد، منبع و شروط حقوقی تغییر نمی‌کنند. همهٔ گزینه‌های بیان برای همان سؤال و همان اولویت‌اند؛ مدل ترتیب شروط را تعیین نمی‌کند.

validator محلی envelope تک‌پاسخ، مدل، پایان کامل، متن JSON محدود، usage معتبر و شناسه/نسخه/بیان مجاز را می‌سنجد. متن ساده، JSON ناقص، refusal، reasoning جدا، tool call، مدل/شناسه جعلی، فیلد تازه مثل گزینه/HTML/قاعده، نبود usage و خروجی بزرگ رد می‌شوند. نبود usage رایگان تلقی نمی‌شود؛ در production اصلاً ارسال تولیدی وجود ندارد. هیچ متن خام، پاسخ provider یا هویت در log اضافه نشده است.

پس از مسیر غیرآنی، نشست و نسخهٔ پرونده دوباره بررسی می‌شوند؛ خروج، حذف یا revision تازه نتیجهٔ قدیمی را فعال نمی‌کند. سؤال تنها همراه پاسخ API تثبیت می‌شود؛ callback برای تعویض عنوان در زمان تایپ وجود ندارد. پاسخ‌های کاربر بدون تغییر منشأ خوداظهاری ذخیره می‌مانند. کارنامه و پایگاه دانش این برش تغییری ندارند.

## پذیرش باقی‌مانده

تأیید هدر endpoint، محدودبودن مجوز ماشین‌یوزر، تعرفه با ارز/مقیاس/تاریخ، JSON و فارسی و latency مدل، سیاست upstream و آزمون از سرور انتشار بدون تماس inference واقعی ممکن نیست. سقف مثبت هنوز مجاز نشده است. ledger هزینه و فعال‌سازی عمومیِ بخش ب انجام نشده‌اند. در این برش هیچ انتشار، migration، DNS، پنل، credential یا بودجه‌ای تغییر نکرد.
