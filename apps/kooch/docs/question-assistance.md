# بیان سؤال و حسابداری AI — تیکت ۰۵

۱۸ اکتبر ۲۰۲۶. توسعهٔ محلی اتصال و کنترل مصرف انجام شده؛ پذیرش production هنوز باز است. بودجهٔ مالک مجموعاً ۵۰ هزار تومان برای آزمون و مصرف ماهانهٔ این مرحله است؛ سیاست سرور آن را ۵۰۰٬۰۰۰ ریال ثبت می‌کند. تعرفهٔ نمایشی و مانع IAM در [بررسی زنده](../../../docs/research/arvan-activation-2026-10-18.md) ثبت‌اند. درخواست‌های تشخیصی ساختگی مستقل از runtime اجرا شده‌اند؛ [نتیجه و حدود پذیرش](../../../docs/research/arvan-connection-contract-2026-10-18.md).

## پروفایل و فعال‌سازی

منبع تنظیمات غیرمحرمانه `data/ai-gateway-policy.json` است. gateway واقعی فقط `https://api.arvancloudai.ir/v1/chat/completions` و مدل `Qwen3.5-35B-A3B` را می‌پذیرد؛ میزبان .invalid برای fixture است. endpoint/model/header از ورودی کاربر پذیرفته نمی‌شوند. مدل فهرست‌شده، قابلیت پذیرفته‌شده و وضعیت بودجه جدا گزارش می‌شوند. task بیان سؤال و تفسیر پاسخ وضعیت جدا دارند؛ پیاده‌سازی تفسیر مربوط به تیکت ۰۶ است و فعلاً خاموش می‌ماند.

پذیرش به fingerprint دقیق نسخهٔ سیاست، connection، alias/model، هویت upstream، نسخهٔ پرامپت/قرارداد/گاردریل و تعرفه و تاریخ انقضا مقید است. تغییر آن‌ها پذیرش قبلی را منتقل نمی‌کند. IAM با دامنهٔ صریح و پذیرفته‌شده، عدم retry درگاه، هدر، قابلیت task و تعرفهٔ معتبرِ شامل همهٔ هزینه‌ها لازم‌اند. نرخ ناشناخته/منقضی، بودجهٔ صفر، پذیرش ناقص یا کلید ناموجود پیش از اتصال مدل، فرم ثابت را برمی‌گردانند. آزمون مستقل هدر apikey را تأیید کرد؛ دامنهٔ IAM با استثنای صریح مالک اکنون workspace-owner است؛ مبنای نرخ منتشرشده با استثنای مالک پذیرفته شده، ولی تأیید provider دربارهٔ همهٔ اقلام صورتحساب ادعا نمی‌شود؛ پذیرش فنی task از سرور انتشار و gate نهایی هنوز باز است.

`KOOCH_ARVAN_API_KEY` فقط بعد از عبور از gate در سرور خوانده می‌شود؛ مقدار آن وارد Git، prompt، خروجی API، JavaScript مرورگر یا log نمی‌شود. `KOOCH_AI_ACCOUNTING_KEY` یک کلید مستقل و ثابت ۳۲بایتی hex برای HMAC حسابداری است؛ نبود آن مسیر تولید runtime را بسته نگه می‌دارد. چرخاندن آن در حضور رزروهای باز، مهاجرت حسابداری لازم دارد. فایل خصوصی آماده‌سازی `.env.arvan.local` خودکار وارد runtime نمی‌شود. کلید، درگاه و ماشین‌یوزر موجود دوباره ساخته نشدند.

## گردش‌کار و مرز مدل

API مالک‌دار `/api/account/form` پس از ثبت پاسخ خودکار سؤال بعدی را می‌دهد. مدل فقط یکی از عنوان‌های فارسی ازپیش‌نوشته‌شدهٔ همان سؤال و همان اولویت را با شناسه انتخاب می‌کند. هفت سؤال عمومی عنوان سادهٔ جایگزین دارند؛ بقیه فقط متن اصلی. متن آزاد مولد یا شخصی‌سازی با مقادیر پروفایل اضافه نشده است. گزینه، کنترل، واحد، help، شروط و قواعد از قرارداد برنامه می‌آیند.

ورودی فقط descriptorهای id/version/title/help/priority سؤال قطعی و عنوان‌های مجاز است؛ پاسخ، پروفایل، revision، case ID، نام، تماس، ایمیل و تاریخچه ارسال نمی‌شوند. شناسهٔ حساب/عملیات فقط در کنترل محلی مالکیت و حسابداری استفاده می‌شود. قبل از ارسال، نشست و revision دوباره بررسی و پس از دریافت نیز خروج/حذف/ویرایش کنترل می‌شوند. سؤال همراه پاسخ API تثبیت می‌شود؛ callback برای تعویض عنوان هنگام تایپ وجود ندارد.

سقف کل کمک مدل، شامل انتظار ledger، ارسال و دریافت header/body و تسویه، ۸ ثانیه است؛ هنگام پایان، فرم ثابت برمی‌گردد و حسابداری معلق در پس‌زمینه، رزرو را حفظ می‌کند. انقضای مهلت در صف اتصال DB نمی‌تواند بعداً درخواست تولیدی بفرستد. کنترل عادی خواندن/ذخیرهٔ پرونده همچنان به در دسترس بودن سرویس حساب وابسته است.

حد خروجی ۱۲۸ توکن است و `chat_template_kwargs.enable_thinking=false` در بدنه فرستاده می‌شود. در آزمون واقعی، تنظیم پیش‌فرض تمام سقف را صرف reasoning کرد؛ با این پارامتر reasoning صفر و متن نهایی دریافت شد. قرارداد جاری `chat-completions-wording-5` است؛ پذیرش نسخه‌های۱ تا۴ منتقل نمی‌شود. نتیجهٔ سادهٔ آزمایش، پذیرش کیفیت انتخاب عنوان فارسی نیست.

بدنهٔ درخواست به‌طور محافظه‌کارانه با UTF-8 bytes به‌علاوهٔ ۵۱۲ برای قالب، زیر کران ورودی ثبت‌شده محدود می‌شود؛ کران ۴۰۹۶، حد انتخابی اپ است، نه ادعای اندازهٔ کانتکست مدل. رعایت حد output و صورتحساب reasoning در تمام شرایط بخشی از پذیرش production باقی‌مانده است. SDK، retry اپ، fan-out، تماس مستقیم با provider یا دنبال‌کردن redirect وجود ندارد. ۴۰۱/۴۰۳ پروفایل را متوقف می‌کنند؛ Retry-After معتبر فقط درخواست‌های تازه را تا حداکثر یک روز محدود می‌کند. تغییر پروفایل برای رفع breaker نیازمند پذیرش تازه است.

validator محلی تک‌پاسخ، مدل، finish_reason، JSON محدود، usage معتبر و شناسه/نسخه/عنوان مجاز را کنترل می‌کند. متن ساده/ناقص، refusal، reasoning جدا، tool call، مدل جعلی، فیلد تازهٔ HTML/گزینه/واحد/قاعده و خروجی بزرگ رد می‌شوند. معتبرنبودن متن، هزینهٔ مصرف‌شده را رایگان نمی‌کند.

قرارداد۵ تنها metadata صریحاً خالی را مجاز می‌داند: annotations=[] یا null و audio/function_call/reasoning/reasoning_content/tool_calls=null. هر محتوای غیرخالی یا کلید ناشناخته رد می‌شود. در سطح choice، index فقط۰ و logprobs/stop_reason/token_ids/routed_experts فقط null مجازند. این فیلدها در capture کامل واقعی آروان دیده شدند؛ فیلدهای غیرخالی پذیرفته نیستند. پس از ثبت کامل envelope و اصلاح قرارداد، هر سه سناریوی سن، مقطع و سابقهٔ کار با پاسخ واقعی از validator اپ عبور کردند؛ هر سه fixed-1 را انتخاب کردند. این پذیرش محلیِ انتخاب مجاز است؛ برتری زبانی یا پذیرش از سرور انتشار ادعا نمی‌شود. هدر apikey نیز با درخواست واقعی تأیید و در سیاست ثبت شد؛ سایر gateها خاموش‌اند.

## رزرو و تسویه

مهاجرت `004-ai-budget.sql` دفتر مشترک PostgreSQL را می‌سازد. HMAC ثابت به‌جای account ID خام ذخیره می‌شود؛ operation key از case/revision/question/version و نسخهٔ سیاست ساخته و hash می‌شود. شناسهٔ رسید مالی تصادفی و از این پیوندها مستقل است؛ رسید پس از پاک‌کردن پیوندهای مالک همچنان برای رسیدگی مالی قابل استفاده است. تکرار همان عملیات، حتی میان چند instance یا پس از timeout، تولید و رزرو تازه ندارد. برای duplicate متن ثابت برمی‌گردد؛ خروجی model prose ذخیره یا بازپخش نمی‌شود.

پیش از هر ارسال، رزرو با قفل همان ردیف مالک که حذف حساب استفاده می‌کند، سپس تحت قفل تراکنشی مشترک، سقف ماهانهٔ سراسری، روزانهٔ سراسری، روزانهٔ کاربر و تعداد درخواست روزانه را با هم می‌سنجد. رقابت روی قفل فوراً fallback می‌دهد و صف عمومی تولید نمی‌سازد. سقف ۲۰ فعلی همهٔ تلاش‌های ارسال‌شده/رزروشده را شامل می‌شود، نه فقط پاسخ‌های موفق. نرخ ۱ درخواست در ۵ دقیقهٔ درگاه مستقل از این سقف‌هاست. دو نمونهٔ سرور و دو مالک با PostgreSQL واقعی آزموده‌اند.

تعرفهٔ همان رزرو snapshot می‌شود. هزینهٔ محافظه‌کارانهٔ هر طرف، جداگانه به واحد ریال رو به بالا گرد می‌شود؛ برای ۴۰۹۶ ورودی و ۱۲۸ خروجی با نرخ نمایشی فعلی، رزرو ۱۷٬۷۴۲ ریال است و از سقف هر درخواست ۱۸٬۰۰۰ ریال کمتر است. این محاسبهٔ محدودکننده، invoice تأییدشدهٔ ارائه‌دهنده نیست. تسویه با usage واقعی انجام می‌شود، حتی اگر متن نامعتبر باشد. فقدان usage، خطا یا قطع پس از ارسال، state نامعلوم و کل رزرو را حفظ می‌کند؛ صفر فرض نمی‌شود. رزروهای باز از نیمه‌شب/ماه و حذف حساب عبور می‌کنند و سقف سراسری را نگه می‌دارند. هزینهٔ بالاتر از رزرو ثبت و پروفایل متوقف می‌شود.

`AiBudgetLedger.reconcile(id, usage, billingReference)` ابزار داخلی برای رسیدگی با شاهد صورتحساب است؛ از تعرفهٔ تاریخی همان درخواست استفاده می‌کند و فقط hash مرجع نگه می‌دارد. endpoint عمومی برای تغییر هزینه یا آزادکردن رزرو وجود ندارد. تسویه idempotent است و مقدار متناقض رد می‌شود. لغو/آزادسازی فقط وقتی caller ثابت می‌کند transport اجرا نشده، مجاز است؛ رزرو نامعلوم انقضای خودکار ندارد.

## نگهداری و عرضه

جدول ledger هیچ متن خام درخواست/پاسخ و account ID ندارد. metadata شامل مدل درخواستی/گزارش‌شده، نسخهٔ سیاست، وضعیت، latency، usage و ارقام حسابداری است؛ متن provider error و هویت به log افزوده نشده‌اند. این گزاره دربارهٔ log اپ است؛ سیاست متریک ۳۰روزهٔ آروان و نگهداری upstream جدا هستند و ادعای عدم نگهداری فراگیر نداریم.

export مالک metadata خودش را می‌دهد؛ حذف حساب، پیوندهای subject و operation_hash را پاک می‌کند و بدهی/رزرو سراسری را آزاد نمی‌کند. job نگهداری، subject قدیمی را پس از ۹۰ روز ناشناس و رکورد بستهٔ غیرمسدود را حذف می‌کند؛ رزرو نامعلوم و breaker باقی می‌مانند. متن خامی برای حذف از provider در این قابلیت ارسال نمی‌شود.

قبل از عرضه، migration 004 و نسخهٔ تازهٔ `db/retention-cleanup.sql` در job میزبان لازم‌اند؛ این نوبت فقط محلی اجرا شدند. پذیرش header/IAM/retry، صورتحساب کامل، JSON/فارسی/latency و smoke از سرور انتشار باقی‌اند. تنظیمات source فعلی عمداً پذیرفته‌شده نیستند. انتشار، تغییر DNS، IAM، credential، بودجهٔ کیف پول یا مدل انجام نشد.


## شرط عرضه پس از آزمون‌های واقعی — ۱۹ اکتبر۲۰۲۶

این بخش وضعیت فعلی را جایگزین عبارت‌های تاریخی آماده‌سازی می‌کند. هدر و انتخاب بیان سؤال محلی تأیید شده‌اند؛ نقش مالک میزکار فقط موقتاً با مجوز صریح داده و سپس حذف شد. IAM محدود یا مجوز دائمی runtime تأیید نشده است. [بازبینی منابع عمومی](../../../docs/research/arvan-unresolved-contract-2026-10-19.md) نیز قرارداد retry و هزینهٔ خطا را نبست.

پیش از هر فعال‌سازی، مصرف آزمون‌های مستقل از runtime باید در همان سقف مشترک۵۰۰٬۰۰۰ریال منظور شود. ledger جدیدِ خالی نشان‌دهندهٔ مصرف صفر این مرحله نیست. مبلغ۲۹٬۶۶۸ریال پنل برای نه پاسخ موفق هنوز غیرقطعی و بدون تأیید شمول همهٔ هزینه‌هاست؛۴۲۹وهر هزینهٔ نامعلوم نیز رایگان فرض نمی‌شوند. رقم باقی‌مانده نباید فقط با کم‌کردن این مبلغ پایه از سقف محاسبه یا سقف کامل به runtime داده شود. تا تطبیق بدهی/رزروهای قبلی با شاهد معتبر و اعمال آن‌ها در حسابداری تولید، فعال‌سازی مجاز نیست. این بررسی، رکورد مالی میزبان یا تنظیمات بودجه را تغییر نداد.

ترتیب پذیرش باقی‌مانده: تعیین دسترسی پایدار مجاز و قرارداد retry/تعرفه؛ تطبیق هزینه‌های قبلی؛ آماده‌سازی migrationهای لازم و job نگهداری در نسخهٔ انتشار؛ پذیرش محدود از سرور انتشار با بودجهٔ جداشده از همان مجموع؛ سپس ثبت fingerprint/انقضا/task فقط برای قرارداد جاری. هیچ‌کدام با دستور صرف ادامه یا GET موفق مدل‌ها پذیرفته‌شده محسوب نمی‌شود.


## کنترل اجرایی مصرف بیرون runtime

`limits.external_hold_minor` اجباری است و مقدار منفی/ناامن/حذف‌شده پذیرفته نیست. مقدار آن مستقل از مالک، همراه مصرف ledger در همان قفل رزرو، به هر دو سقف روزانه/ماهانهٔ جهانی افزوده می‌شود؛ سهمیهٔ شخصیِ متقاضی بابت آزمون‌های اپ مصرف نمی‌شود. hold با مرز روز/ماه خودکار آزاد نمی‌شود. اگر همین hold جای یک رزرو تازه را نگذارد، gate پیش از کلید یا DB، سؤال ثابت با budget_exhausted می‌دهد. تغییر hold fingerprint قبلی را نامعتبر می‌کند.

سیاست فعلی۵۰۰٬۰۰۰ریال را تا تطبیق مستند نگه می‌دارد؛ این رقم خرج واقعی یا صورتحساب نیست. تنها هزینه‌های مستقل بیرون ledger در آن منظور شوند؛ افزودن مجدد رکوردهای runtime دوباره‌شماری است. کاهش hold پس از تطبیق معتبر، با پذیرش تازهٔ اتصال انجام می‌شود. تنظیم فعلی قیمت/IAM/task را تأیید نمی‌کند و هیچ مصرف عمومی ایجاد نکرد.


## دامنهٔ دسترسی دائمی — وضعیت جاری۱۹اکتبر

مالک نگه‌داشتن دائمی نقش «مالک میزکار» برای kooch-ai در میزکار اصلی را صریحاً تأیید کرد. قانون kooch-ai-workspace-owner ثبت و در قوانین متصل همان ماشین‌یوزر مشاهده شد؛ تا دستور صریح لغو باقی می‌ماند. این استثنا همهٔ سرویس‌های میزکار، از جملهDNSوIAM را پوشش می‌دهد و محدود به مدلAI نیست.

`acceptance.iam_scope` دامنه را به‌صورت resource-scoped یا workspace-owner، و null برای نپذیرفته ثبت می‌کند. منبع فعلی workspace-owner است؛ scope بخشی از fingerprint است و تغییر آن پذیرش قبلی را منتقل نمی‌کند. ساختار قدیمی iam_scoped با schema سخت‌گیرانه رد می‌شود. باقی کنترل‌ها تغییری نکردند؛ این ثبتِ دامنه به‌تنهایی مجوز inference یا انتشار نیست. بخش‌های پیشین دربارهٔ لغو نقش موقت تاریخی‌اند؛ این بخش وضعیت جاری دسترسی را مشخص می‌کند.


## مبنای تعرفهٔ پذیرفته‌شده توسط مالک — وضعیت جاری۱۹اکتبر

مالک هزینه را بر مبنای نرخ منتشرشده پذیرفت. `acceptance.published_tariff_accepted=true` اجازه می‌دهد نرخ موجود با وجود all_charges_included=false مبنای محاسبه باشد؛ تأیید جامع صورتحساب جعل نمی‌شود. این پرچم اجباری و به fingerprint وابسته است. نبود تعرفه، انقضا، ارز ناسازگار،کران هزینهٔ نامعتبر و سایر gateها همچنان رد می‌شوند. verified_atهمان مشاهدهٔ۱۸اکتبر است؛ اعتبار فرض محلی تا۲۰اکتبر۰۷:۴۳:۴۴UTC تعیین شد، نه تأیید دوبارهٔ provider.

[دفتر تطبیق نرخ پذیرفته‌شده](../../../.scratch/kooch-self-service-app/evidence/arvan-owner-accepted-pricing-2026-10-19.json) نُه رسید موفق را به۲۹٬۶۷۶ریال پایهٔ محافظه‌کارانه تبدیل و۱۸٬۰۰۰ریال برای۴۲۹بدونusage حفظ می‌کند. external_hold_minor اکنون۴۷٬۶۷۶ریال و باقی‌ماندهٔ محاسباتی۴۵۲٬۳۲۴ریال است؛ فقط روی مبنای نرخ پذیرفته‌شده،نه تضمین invoiceنهایی شامل همهٔ اقلام. مقدار کامل۵۰۰٬۰۰۰ریالی در بخش‌های تاریخی دیگر وضعیت جاری نیست. هیچ هزینهٔ خطای نامعلوم صفر نشده یا به کاربر خاص نسبت داده نشده است. production هنوز به دلیل پذیرش فنی تکمیل‌نشده خاموش است.

## Protected Preview account login

A dedicated `kooch_preview_account_api` login can inherit the existing app permissions on PostgreSQL16+ with `GRANT kooch_account_api ... WITH INHERIT TRUE, SET FALSE`. It receives a separate `kooch_runtime` membership with `INHERIT FALSE, SET TRUE` for owner-scoped case transactions. It must not use a default role or gain SET access to the Production login. Runtime checks require the exact Preview name, direct login, finite unexpired password validity and no superuser/BYPASSRLS/CREATEROLE/CREATEDB/replication privileges. This shares the app database and its permitted operations; it is not a separate data environment. A real PostgreSQL test covers sessions, ledger reservations, owner isolation and refusal to assume or modify the Production role. Hosted pooler compatibility remains subject to actual Preview acceptance.

Human-only credential submission is prepared in the dated browser SQL template under the local ticket tracker; its blank value fails before creating a role. After the approved batch (including failure), run the companion disable SQL: NOLOGIN, revoke both memberships and terminate only this login’s sessions. VALID UNTIL alone does not revoke memberships or close existing sessions. Do not rotate the Production password or remove accounting keys with unresolved holds.
