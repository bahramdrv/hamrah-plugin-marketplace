# Domain docs

Hamrah uses one domain context. Before exploring or changing a domain behavior, read the root `CONTEXT.md` and the ADRs in `docs/adr/` that cover the area. Use the glossary's terms in tickets, code, tests, and user-facing explanations; its “Avoid” entries identify misleading aliases.

When a proposed change conflicts with an ADR, state the conflict and resolve the decision before implementation. Record new hard-to-reverse decisions in `docs/adr/` and update `CONTEXT.md` when the domain vocabulary changes.
