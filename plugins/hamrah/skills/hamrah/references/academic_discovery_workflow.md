# Academic Discovery: APIs, current official evidence and a consistent report

Use this workflow on an explicit university, program, supervisor, position or funding request. A prior immigration assessment and complete profile are optional. The product owner selected ROR, OpenAlex, Crossref, official/ATS/JSearch and Tavily for the first phase; source failures still require bounded host web research. Each provider has partial coverage.

1. Call `discoverAcademicMatches` with public type/field/topic/institution/country terms. Send no applicant profile, name, contact or private document. Equivalent registered Persian/English topic aliases use a canonical query plan. With incomplete information, return an exploratory answer and ask only questions that improve the next search. Request at most ten main results.
2. Use API candidates and host web search to find exact official institutional pages. Programs, admissions intakes, supervisor research, recruitment, research vacancies, scholarships and awarded grants are separate. For faculty candidates, verify the public professional name and current institutional affiliation before displaying a name. A publication affiliation is not current employment.
3. Find the institution's ROR identity and its official website. Read the exact official program/faculty/posting page in the current request; record literal excerpts for its title and each relevant claim. For supervisors include an `affiliation` excerpt explicitly containing the supplied professional name/title and institution and supporting current membership, plus a research excerpt; a seminar listing, former membership or publication address is insufficient. For programs include actual admission requirements, not just descriptions. For open calls include a currently supported dated or rolling application window; for funding specify guaranteed-position funding versus a competitive award. An awarded research grant is a separate fact and establishes no free student budget.
4. Call `verifyAcademicEvidence` for each record using ROR identity and literal public excerpts. The tool checks current content and publisher identity, follows bounded same-origin redirects, and requires institutional delegation for external job-board URLs. A blocked document, mismatched excerpt, missing authority or expired/ambiguous window stays unverified. Continue browser/host research for JS pages, PDFs and other unsupported sources; do not manufacture a verification token or silently upgrade a candidate. The conservative parser does not support every language/date syntax. Describe those gaps truthfully.
5. Call `renderAcademicDiscoveryReport` with the original public request, fresh evidence tokens, minimal candidate records and actual source coverage. The renderer checks signatures/freshness, requested scope, research relevance and explicit guaranteed-funding constraints. Keep research rank separate from funding and Iranian eligibility. Preserve its Persian output. It is evidence comparison, not admission probability.
6. Compare private applicant facts locally, following `hamrah-program-finder/references/matching_contract.md`. Apply known hard admission and nationality restrictions before personal ranking; missing evidence stays unknown. When personal fit notes are useful, run `hamrah-program-finder/scripts/render_academic_discovery_fit_notes.mjs` locally with `publicReport` and one `fitNotes` entry per verified result. Each note has `resultId`, `checks` (`claimIndex`, `result`: met/not_met/unknown, `applicantEvidence`) and `gaps`. Checks reference actual official requirement claims. The script uses the same formatter, removes unmet official requirements from the personal main list and adds source-linked private comparisons. Keep the original public report, these inputs and the final personal report in the conversation/requested file; never put them in shared Redis or remote renderer arguments.
7. Explain actual source/country coverage, truncation, failures and remaining unknowns. Keep relevant unverified candidates in their separate section. Missing results are not proof of no opportunity. Continue the same search with narrower topic/country/institution or additional candidates when requested; no automatic worldwide crawl runs.
8. For replay/export, keep the private public-report JSON, signed evidence tokens, local fit notes and policy versions in the requested local file. Supply prior signed tokens as `previousEvidenceTokens` on a later render to explain evidence changes; old tokens never establish current verification. A source-hash difference explains changed evidence, not an applicant score. Key rotation can make a prior signature unverifiable; do not invent a change conclusion in that case.

Shared storage is limited to licensed minimal ROR, Crossref factual metadata and OpenAlex award candidates with seven-day expiry and ten-minute reuse. It stores no web snippets, official excerpts, verification conclusions, contacts or applicant history. Reads do not extend record expiry. The existing supervisor/JobTech stores keep their own policies. A cached candidate is always unverified.
