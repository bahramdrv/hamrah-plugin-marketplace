# Open academic calls: free API leads and live official verification

Use this path only after an explicit request for a specific open Master's or PhD admission/funding call, doctoral or postdoctoral vacancy, or research job. It does not search professors or general university rankings. A program's existence, a professor profile, or a search result is not an open call.

1. Obtain the requested research field/topic and target category (`masters`, `phd`, `postdoc`, or `research_job`). If either is absent, return one targeted `needs_input` question. Country is optional; an omitted country permits a bounded global search. Record whether funding is required. Do not demand a complete immigration profile.
2. Call `discoverAcademicCallCandidates` with only field, category, optional ISO alpha-2 country, and a bounded limit. For Master's in Finland or a global Master's request, it queries the free public Studyinfo (Opintopolku) external API with a required `Caller-Id`, then checks each exact admission target's published status and application window in Finland local time. It returns only title-matched Master's targets whose window is currently open; the API lead still requires current official page verification. It excludes obvious internal-transfer and degree-completion pathways. Open UAS and Finnish-prior-study pathways may appear with `admissionPathway: "restricted_prior_studies"` and a warning, after other pathways; verify prior-credit, work-experience, language, and nationality requirements before presenting one as suitable. The API covers Finland only, and query pagination/detail limits can truncate discovery. For PhD it reads the free DAAD PhDGermany feed where Germany is in scope. For global or US postdoctoral/research-job searches it checks the public Toyota Research Institute Lever board and the public Greenhouse board linked from Ai2's official careers page. The Ai2 board supplies US research jobs and its Young Investigator postdoctoral program only; predoc and internships are excluded. For research jobs it also checks the public Institute of Foundation Models Lever board on global, US, AE, and FR requests; its checked postings span those three countries only. Global or Canadian research-job requests additionally check Waabi's public Lever board, limited to postings whose API primary country is `CA` and whose title matches the requested field; multi-location postings with another primary country are not claimed as Canadian coverage. Global or British research-job requests check Faculty's public Ashby board, limited to listed postings with a `United Kingdom` primary address, mapped to ISO `GB`, and a title match. IonQ's public Greenhouse board supplements global and supported-country research-job searches; accept only a field-matched research/scientist/fellow title with an exact IonQ posting URL and a recognized primary `location.name`. Its `offices` list may contain countries that are not the posting's actual work location, so never use it for the country match. IonQ results are unverified leads until the exact official posting confirms current application terms. For another public Lever publisher board found through an official employer posting, the board's published site identifier may be supplied as `publisherBoards: [{provider:"lever",boardId:"..."}]`; this adds to eligible default boards and a duplicate board is fetched once. Never guess a board identifier or claim it covers other institutions. A response with `verificationStatus: "unverified"` is a lead only. If an API fails or does not cover the category/country, keep the failure/coverage in the final report.
   Studyinfo checks at most two search pages and twelve distinct programme details; `coverage.truncated` indicates anything beyond that budget. A failed second page preserves first-page leads and marks partial coverage. The discovery tool omits non-Studyinfo leads with a recognized deadline on or before today's UTC date and reports `expiredKnownCount`. Studyinfo admissions instead use the exact Finland-local application window, including a deadline later today. Unknown or absent deadline text from other sources remains an unverified lead; only the official publisher can establish an open call.
   Keep explicit postdoctoral and predoctoral titles out of `research_job` results, even if they also contain “researcher” or “scientist.” A postdoctoral title belongs to the `postdoc` request; a generic research-job request does not silently relabel it. For Ai2, require the primary Greenhouse `location.name` to agree with a US office location before mapping the candidate to `US`; an office list by itself is insufficient.
   For US/global `postdoc` searches, also check Arc Institute's public Greenhouse board. Keep only explicit postdoctoral titles matching the requested field and an exact Arc job URL; require primary `Palo Alto, CA` plus the matching US office. Other locations are outside this source's validated scope. Its Apply form and API listing are discovery evidence only: without a current dated deadline or explicit rolling terms on the exact publisher page, do not promote the call to verified-open results.
   For NZ/global `postdoc` searches, also use the free public SmartRecruiters Posting API for the University of Auckland. Scan at most 100 public list entries and fetch at most twelve field-matched exact details. Require an explicit postdoctoral title, `nz` primary country, university publisher identity, `PUBLIC` visibility, active exact detail, and its canonical official posting URL. Mark omitted list/detail records as truncation and detail failures as partial coverage. The active API flag alone does not verify the open call; inspect the exact official page for a current deadline or explicit rolling terms, application instructions, qualifications, funding and any nationality restriction before including it in the report.
   For CA/global `postdoc` searches, also use University Health Network's free public SmartRecruiters postings with `q=postdoctoral`. Apply the same 100-list/twelve-detail bounds and require an explicit field-matched postdoctoral title, `ca` primary country, UHN publisher identity, `PUBLIC` visibility, active matching exact detail, and its canonical UHN posting URL. The text query can miss other postdoc wording, and this one publisher cannot represent all Canadian openings. Report truncation and failures; verify current acceptance, a deadline or explicit rolling terms, and every material condition on the exact official page before rendering any lead as open.
3. Also search the live public web within the requested scope. Use current official university, program, funding-body, research-institution, and employer pages to find and verify calls. EURAXESS or other indexes can provide leads, but cannot establish decisive facts. Inspect the exact official call and its application page. Search another official page when a material detail is missing; if still unsupported, exclude the candidate and record a reason. Do not silently widen a specified country or field.
4. A displayed call needs an exact official title, a current official statement or active application path that establishes acceptance now, a future dated deadline or explicit rolling application, all material published eligibility and selection conditions for the exact intake, and a check date for every source. Inspect the exact admission target's selection criteria, not only the programme overview; record degree, work experience, test and language thresholds when published. The renderer's minimum of one condition is structural and does not establish that the list is complete. A future deadline without current acceptance is insufficient; the dated-call renderer also rejects an excerpt without positive wording that applications are open or invites an application now. If a publisher specifies the closing time and timezone, pass optional `application.deadlineAt` as an ISO timestamp with offset whose local date matches `deadline`; this allows a call open for part of the final day and rejects it after that instant. Without a sourced exact time, a deadline on today's UTC date remains excluded. For rolling mode, quote the official wording that explicitly says applications are continuous or accepted until filled; an Apply button alone does not qualify. If the source says applications are closed or not open yet, exclude the lead even when another date is future. Keep Master's/PhD admissions, their distinct scholarship calls, and research vacancies under separate `kind` values. A scholarship can link to an admission when official terms cover the named program/intake or a broader class that demonstrably includes them. Competitive eligibility never means an award is guaranteed; represent a competitive scholarship as a separate `funding_call`, never as a vacancy's or admission's own `funding.status`.
5. For `fundingRequired: true`, omit vacancies whose financial terms are unknown; show separately a source-backed competitive funding call linked to an admission. For a general request, unknown funding may appear with `unknown`. Preserve official salary/stipend terms, workload, duration, and scholarship coverage separately. Official silence on Iranian nationality is `unknown`; an explicit official exclusion is a cited exclusion, not a shortlisted result. Do not calculate an Iran-compatibility, admission, or visa percentage.
6. Deduplicate by the exact official posting/application identity. Aim for three to five verified results, or fewer including zero. Order by source-backed field/condition relevance using only supplied academic facts, then verified financial status, then deadline and stable URL tie-break. Unknown applicant facts remain `unverified`; do not turn missing facts into support. Keep applicant-specific comparisons local and out of MCP calls.
7. Call `renderOpenAcademicCallReport` with public facts only. Pass today's UTC `checkedAt`, scope including `fundingRequired`, coverage for every attempted API and web search, excluded candidate counts/reasons, and the verified calls. `candidatesChecked` equals displayed calls plus exclusions. Every cited excerpt must be checked against the live official page before this call; the renderer validates shape and consistency, not the live page. If a source failed or timed out, mark partial coverage. With no verified calls, preserve `no_verified_results` or `research_required`; never infer that no opportunities exist. Keep the returned Persian block intact. If applicant facts exist, run `render_academic_call_fit_notes.mjs` locally with the exact `publicReport` structured content and one `fitNotes` entry per result in the same order, covering every published condition with `supported`, `unverified`, or `not_met`, a reason and a gap for non-supported conditions. Paste its complete output; never send these notes to MCP.
8. Give one concrete next action. Before the applicant acts, recheck the selected official application page because its status can change. Do not persist request results as a standing catalog or send an application.

The older `renderVerifiedOpenAcademicOpportunityShortlist` contract remains for its narrow Germany/Physics/PhD replay. Use the new discovery and report path for general searches.
