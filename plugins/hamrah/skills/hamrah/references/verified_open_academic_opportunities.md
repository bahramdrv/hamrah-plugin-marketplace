# Verified Open Academic Opportunity — first live-search slice

Use this path only when the user explicitly asks for an advertised funded doctoral research opening. The first acceptance scope is physics in Germany. A named university, professor, laboratory, program, or `active` Academic Opportunity store record is a lead, not proof of a current vacancy. Do not require a complete immigration intake or scorecard.

1. Search current public university, research institution, or official employer advertisements for the requested country, field, and degree. Open each candidate's actual advertisement and its application and funding pages as needed. Do not search automatically without a request, use private or login-only pages, or treat an old store result as current. If live browsing is unavailable, return `research_required` with the missing source requirement; do not use stale results to fill the gap.
2. Confirm on current official pages that the exact doctoral opening is advertised, applications are being accepted **now**, and the call has either a future dated deadline for that opening or an explicitly rolling application period. Record the date checked and a short exact excerpt plus URL for the advertisement and application state. A future deadline alone does not establish that applications are open. A recurring day/month without a stated year is not a dated deadline. Exclude filled, withdrawn, expired, and uncertain calls from a verified-open result.
3. Confirm salary or stipend terms for that exact opening from a current official source. Record the salary scale, a positive amount with currency and period, or a named stipend package with its published terms. A generic “funding available” statement, a competitive award not attached to the opening, a rumor, or conflicting official statements does not establish verified funding. If compensation cannot be confirmed, omit the candidate from this funded slice and explain the coverage limit.
4. Keep the first search within Germany (`DEU`), doctoral level (`phd`) and physics (`Physics`). Check enough current official candidates to aim for three to five qualified openings, but return the actual number, including zero. Count every candidate inspected and record excluded candidates by the renderer's public reason codes: `not_currently_open`, `expired_deadline`, `unverified_funding`, `missing_official_posting`, `out_of_scope`, `unverified_conditions`, or `other_unverified`. Do not silently widen the requested scope or claim that an empty result means no position exists.
5. Call `renderVerifiedOpenAcademicOpportunityShortlist` with public facts only: a current check date, `searchScope`, `coverage`, and up to five `openings`. Each opening needs the exact title, institution, country, degree, field, official posting URL and excerpt, and at least one source-linked published academic condition. Add `nationalityEvidence: { status: "unknown", sourceUrl: null, sourceExcerpt: null }` when the official pages are silent about Iranian nationality; silence does not establish permission or restriction. The currently accepted public renderer shape covers this unknown case; leave a sourced exclusion for explicit restrictions to the next slice. For each opening, set `application.status: "open"`, `mode: "dated"` with a future ISO deadline or `mode: "rolling"` with a null deadline, plus an exact current-acceptance excerpt and source. Quote the opening title from the posting itself. A dated deadline excerpt must contain its complete day, month, and year. For funding, use exactly one of a salary scale, an amount with currency and period, or a named stipend package with `packageTerms`; copy the decisive terms from the official funding excerpt, including the payment period when an amount is stated. The renderer checks structure and that caller-supplied excerpts contain stated details; it does not authenticate pages or judge their full meaning. Verify each excerpt against its current official page before the call. If validation fails, correct the record from the source or omit it; never relax a gate or invent a field.
6. Keep the tool's primary Markdown text intact. Compare only academic facts the applicant supplied with every published condition, then run the bundled local `render_opportunity_fit_notes.mjs` with JSON on stdin. Set `rendererMarkdown` to the exact MCP text and give `fitNotes` one entry per opening in the same order, each with one `comparisons` entry per academic condition. Each comparison has `status` (`supported`, `unverified`, or `not_met`), a short applicant-specific `reason`, and a `gap` when status is not `supported`. A missing diploma, course record, language proof, or other decisive fact is `unverified`, never assumed met. For zero openings pass an empty `fitNotes` array. Paste the script's complete output so the validated public blocks and linked private fit notes stay together. Applicant identity, profile facts, personal reasons, and gaps must not enter the remote MCP call or published datasets. Do not report an admission or visa probability. Give a concise next action and at most one decision-changing question.

Do not turn this opening into an Academic Program Match, professor recommendation, official immigration eligibility finding, or admission/visa probability. If no candidate passes the checks, say which evidence is missing; missing coverage is not proof that no opening exists.
